Wireless Security

Security protocols

  • WEP – RC4-based, broken in minutes. Don't use!
  • WPA – TKIP encryption, outdated and vulnerable
  • WPA2 – AES-CCMP based, secure with a strong password
  • WPA3 – SAE protocol, best current protection
Testing requires a monitor-mode WiFi adapter (not available on macOS).

WPA2 – 4-Way Handshake

The password never travels over the air — only a mathematical digest (MIC). If we capture the 4 EAPOL packets, we can try to guess the password with offline brute-force. The router can no longer block the attempts.

  • M1: Router → ANonce (random number)
  • M2: Client → SNonce + MIC (computed from password)
  • M3-M4: mutual confirmation

PMKID Attack – Clientless

A method discovered in 2018: we can obtain the password hash without any clients present. With a single Association Request packet, the router returns a PMKID containing the password hash — no handshake capture needed.

This is the most modern WiFi audit technique — wifite tries it automatically.

WPS and Pixie-Dust vulnerability

The 8-digit WPS PIN is actually split into two parts — the first 4 digits can be verified independently. This drastically reduces brute-force time (11,000 attempts instead of 11 million).

The Pixie-Dust attack on certain chips (Ralink, Realtek) figures out the PIN from a single packet exchange — because they generate random numbers incorrectly.

Deauthentication attack

The 802.11 management frames (Beacon, Deauth) are unencrypted. An attacker can send a "disconnect" command on behalf of the router to the client, who immediately reconnects — this is when the 4-way handshake can be captured.

wifite performs this automatically during testing.
